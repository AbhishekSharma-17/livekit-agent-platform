# LKAP v4 — Custom model ids, live catalogs and "Test model"

Status: **decided** (Fable 5.1, 2026-09-25). Findings first, then the design. Decisions continue `PHONE-NUMBERS.md`'s numbering at **D-V4-23**; package cards V4-07 … V4-10 and rulings R-V4-21 … R-V4-28 are in `PLAN-V4.md`. Sequenced after V4-04 (the OpenRouter console package, live in `web/src/components/console/registry/**` today).

The user's words, paraphrased: *"In providers the catalog is fixed. Add an option so we can provide a model name ourselves. OpenRouter has so many models, and when any provider releases a new one, how will that be added? We should be able to test and validate it as well."*

Short answer. The registry is already a suggestion list, not an allowlist (CONTRACTS.md §"Validation rules": free text is a warning, never an error; `ModelSpec`'s docstring says the same), and the console's model combobox already has a "Use "<typed>" as a custom id" row — but only for the entries that carry a `models` list. Three things are missing and this design adds them: (1) **custom ids everywhere**, with one id rule, no secret ever echoed, and a way to say what a custom model can do; (2) **live catalogs** wired to every vendor that has a list API, filtered per slot, searchable, with the cache we already have; (3) **"Test model"** — one real, capped vendor call from the api process that reports ok / latency / detected capabilities / cost, stored per workspace and shown as a "Tested ✓" chip, feeding validation as a warning, never an error. A weekly CI drift job and a promotion rule keep the registry defaults honest, and a model that disappears upstream becomes a warning on every agent using it.

## 1. Findings (accessed 2026-09-25)

### 1.1 How models work today (read from HEAD `2cbd43f`)

- **Contracts.** `ProviderSpec.models: list[ModelSpec]` (`id`, `label`, `supports_video`, `note`), `default_model`, `catalog: CatalogSpec(adapter, kinds, ttl_s)`, `test: str` (the credential-test adapter; the docstring invariant is `test == catalog.adapter`). `ProviderRef.model: str | None` is free text (`lkap_contracts/common.py`). `vision_support(provider_id, model)` returns `True/False` for a listed model and `None` for anything else (D-W2-10). `FieldType` already contains `"model"` and `"catalog"`; **no registry entry uses `type="model"`** (`grep -c 'type="model"'` → 0) while **27 entries carry `FieldSpec(name="model", type="string")`** (AssemblyAI, Google STT, OpenAI STT, Groq STT, Speechify, Soniox, MiniMax, …) instead of `models`/`default_model`.
- **Validation** (`config_service.py`). `_validate_model` warns `model '<id>' is not in the suggestion list for '<provider>' (free text is allowed; vendor model lists change often)` — and interpolates the typed value into the message, which lands in `ValidationResult`, the audit payload and the console. `_validate_modes` warns on `vision_support(...) is False` only; `None` (a custom id) is silent. `_validate_fields` accepts any string for `type="string"`/`"catalog"` fields, and its enum error echoes the value too (`… (got '{value}')`, `config_service.py:558`) — a key pasted into an enum-typed `voice` field comes back through a built-in check that runs before any registered validator.
- **Worker.** `factory._constructor_kwargs` passes `provider.model or spec.default_model` as `model=` for every kind except avatar/vad/turn/noise; a `fields.model` value survives when both are `None`. `platform_agent.model_vision_support` returns `None` for a custom id and **per-turn vision is skipped only on `False`**: a custom text-only model receives image parts every turn and the vendor rejects them (or silently drops them). `describe_current_frame` behaves the same. The worker has **no inbound surface**: `registration.py` registers and heartbeats outbound; sessions arrive by LiveKit dispatch.
- **Catalogs** (`api/src/lkap_api/catalogs/`). One `HttpCatalogAdapter` tree (13 vendors) plus `OpenRouterCatalogAdapter` ×5 (V4-03, `/key` probe then a filtered `/models`). **`service.get_catalog` resolves the adapter from `spec.test`, not `spec.catalog.adapter`** (`service.py:83`), and returns the static fallback whenever the secret bag is empty (`:84`) — so a catalog-only entry, or a public list that must not be the credential test, never gets a live fetch today. `parse_items` is lenient; `CatalogItem.meta` keeps the raw item (OpenRouter trims it to pricing/context/architecture/supported_parameters/supported_voices). Cache: `provider_catalog_cache` keyed `(provider_id, credential_id, kind)`, TTL from `CatalogSpec.ttl_s` (1 h), `refresh=true` bypass, fallback chain fresh → live → stale → static → empty. No pagination: adapters do one GET. No search: `GET /v1/providers/{id}/catalog` has no `q`.
- **Credential tests** run the catalog adapter with a 10 s timeout and cache 10 min on the credential row (`last_test_*`); the api-process precedents for a *real* vendor call are `qa/llm_client.OpenAiCompatibleJudgeLLM` (chat completions over `httpx`) and `kb/embed.OpenAIEmbedder` (`/embeddings`). Every outbound call goes through `net_guard` (`HttpClientDep`; `GuardedTCPConnector` for aiohttp, which `api/uv.lock` already carries).
- **Console.** `ModelCombobox` (Suggested group + a Custom row + "Vision only" toggle) is rendered by `ProviderSlotEditor` **only when `models` is non-empty or `default_model` is set** (`showModel`), so the 27 string-typed entries get a bare text box under Options. `registry-form.tsx` already special-cases `field.type === "model"` (mono text) and renders `type="catalog"` fields through `CatalogPickerField` (a `Select` with "Paste id manually…"; manual becomes the default view when the catalog is empty or the stored id is unknown). The Providers page's Catalog dialog lists the first kind with a Refresh button. `ProviderSlotCard` shows `ModelSummary` ("Custom model" for an unknown id) and capability badges from the *provider*, never the model.
- **MCP.** `provider_catalog(provider_id, kind, key_id?, refresh?)` (`providers:read`, READ, labels wrapped as `untrusted`), `provider_key_test` (`providers:write`). Route policy: `/v1/providers` is `viewer`+`providers:read` to read and `admin`+`providers:write` to write; the longest route-*template* prefix wins (`roles.policy_for`), so a more specific `_Rule` can carve out one route.
- **Pricing.** `pricing.lookup(provider_id, model, unit)` returns `None` for anything unpriced (the designed safe path: `note="no price"`). Priced today: OpenAI LLM/TTS, Google LLM, Deepgram STT/TTS, LiveKit Inference STT/LLM/TTS.
- **Rate limiting.** `RateLimiter.hit(key, capacity, per_seconds)` is a named token bucket (`InMemory` or Redis); any route can hit its own key.
- **Migrations.** HANDOFF rule 4: only `v4_001_livekit_numbers` is authorised in v4 (R-V4-11). Nothing today stores a per-model fact: `Credential` has `last_test_*` for the key, `ProviderCatalogCache` holds vendor lists, `AgentConfig` holds a `ProviderRef`.

### 1.3 What the api process can call, per kind, to test a model

All OpenAI-shaped vendors share one wire adapter with a `base_url`: OpenAI, OpenRouter, Groq, Cerebras, xAI, Mistral, Together, Fireworks, `openai-compatible-llm`, and **LiveKit Inference LLM** (`https://agent-gateway.livekit.cloud/v1/chat/completions`, bearer = the project JWT; `inference/llm.py:272`). Anthropic is `POST /v1/messages`; Gemini is `POST /v1beta/models/{model}:generateContent` (and `:embedContent`); Gemini Live and OpenAI Realtime are websocket handshakes (`wss://api.openai.com/v1/realtime?model=…` then `session.created`; `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent` with a `setup` message and its `setupComplete` reply — the exact frames are UNVERIFIED here and are read from the installed plugin source by the package). TTS: OpenAI/OpenRouter `POST /audio/speech`; Deepgram `POST /v1/speak?model=aura-2-<voice>-en` with `{"text": …}` returning audio bytes ([Deepgram speak](https://developers.deepgram.com/reference/text-to-speech-api/speak)); ElevenLabs `POST /v1/text-to-speech/{voice_id}?output_format=…` with `model_id`; Cartesia `POST /tts/bytes`. STT: OpenAI/OpenRouter/Groq `POST /audio/transcriptions` (multipart, ≤ 25 MB); Deepgram `POST /v1/listen?model=…` with raw audio. Embeddings: `POST /embeddings` (OpenAI shape) or Gemini `:embedContent`. Images: **not probed** (every generation costs money; catalog membership only). Avatars: **session-less only** — `GET /v1/avatars/{id}` (bey), `GET /v2/replicas/{id}` (Tavus), Simli faces list membership; never a session.

### 1.4 Discrepancies and gaps this pass surfaced (filed as asks, neither side asserted)

1. `cartesia_voices` sends `X-API-Key` + `Cartesia-Version: 2024-06-10`; the current page documents `Authorization: Bearer` + `2026-08-14`. Both answer 401 to a bogus key; which works with a real key is settled in the live check.
2. `hume_voices` sends no `provider` query parameter; Hume's page marks it required.
3. `elevenlabs_voices` uses `GET /v1/voices`; the documented, paginated list is `/v2/voices` (v1 status unstated).
4. Deepgram's `/v1/models` is public; it can be a catalog but never the credential test (R-V4-9). `_TEST_CALLS["deepgram-stt"]` stays on `/v1/projects`.
5. `google-realtime` has no catalog although Gemini's list carries `bidiGenerateContent` per model — the one place a realtime model list exists.
6. The worker skips per-turn vision only on `False`; a custom text-only LLM gets image parts (§1.1).
7. `azure-tts`/`azure-stt` voices can only be listed with the slot's `speech_region`; `GET /v1/providers/{id}/catalog` is provider-level (credential only). A `fields`-aware catalog route is a later decision, not built here.
8. `service.get_catalog` keys the adapter by `spec.test` and skips the fetch with an empty secret bag (§1.1) — fixed by V4-07 (D-V4-25), because public lists must be catalogs without being credential tests (R-V4-9).

## 2. Design

### D-V4-23 — Custom ids are first-class: one id rule, no echo, unknown stays a warning, `type="model"` everywhere

**Rule (contracts, `lkap_contracts/providers.py`).** `validate_model_id(value: str) -> str | None` returns a secret-free reason or `None`:

1. **Secret-looking values are refused first and never echoed.** A value that starts with a known key prefix (`sk-`, `sk_` (ElevenLabs), `sk-or-`, `sk-ant-`, `sk_car_`, `AIza`, `xai-`, `gsk_`, `hf_`, `AKIA`, `ghp_`, `ya29.`, `xi-`… — `SECRET_PREFIXES`, one tuple, extended by tests) or is a **bare token**: ≥ 32 characters from one character class (hex, or base64/`[A-Za-z0-9]`) with no `/`, `.`, `:` or `-` separator (catches 32-hex Tavus/Simli-style keys; `gemini-2.5-flash-native-audio-preview-12-2025` has separators and passes) → reason `"looks like an API key, not a model id"`. The message contains no part of the value. The same check runs on every `type="model"`/`type="catalog"` field and on `voice`, `voice_id`, `avatar_id`, `face_id`, `pal_id`, `persona_id`, `voice_name`, `emotion_id` (`ID_LIKE_FIELD_NAMES`). **No built-in check may echo either**: `_validate_fields`' enum error drops its `(got '<value>')` suffix and names the field instead — the one existing echo path (§1.1).
   *Amended by R-V4-31 (2026-09-25):* the **prefix** half of this check is an error on every field, but the **bare-token** half is an error only for model ids (`ProviderRef.model`, `type="model"` fields, the `/models/{model_id}` routes, `ModelTestRequest.model`); on `ID_LIKE_FIELD_NAMES` and `type="catalog"` fields a bare token is a value-free **warning** ("the value looks like an API key; if it is the vendor's id, ignore this"), because a vendor whose real avatar or voice ids are 32-hex strings must stay usable. `validate_model_id` is unchanged; `validate_id_value(value) -> IdIssue | None` carries the split; `ModelIdRules` is unchanged and the console applies the split by field type. The `/models/{model_id}` path stays as designed (R-V4-32): the console and the MCP validate before they send, and the HTTP server's access log is a stated limitation in `RUNBOOK.md`.
2. **Syntax.** 1–200 characters; printable ASCII; no whitespace or control characters; no `://`, `?`, `#`, `&`, `=`, `<`, `>`, `"`, `'`, `` ` ``; may not start with `http`. Everything a real id needs is admitted: `/`, `.`, `_`, `:`, `@`, `+`, `-` (`amazon.nova-2-lite-v1:0`, `openai/gpt-4o-mini:free`, `BAAI/bge-small-en-v1.5`, `cartesia/sonic-3:<uuid>`, `accounts/fireworks/models/…`, `ft:gpt-4o-mini:org::abc`). `MODEL_ID_PATTERN` is exported for the console: `ProvidersResponse.model_id_rules: ModelIdRules | None = None` (additive: `pattern`, `secret_prefixes`, `max_len`, `bare_token_min_len`) is filled by `export.build_providers_document` and by `GET /v1/providers`, so `providers.json` stays a strict `ProvidersResponse` (the MCP's `content.py` and the web fixtures parse it as one).
3. **Unknown is a warning, not an error** — unchanged from CONTRACTS.md and D-W2-10. The warning text no longer interpolates the value: `pipeline.llm: this model id is not in the suggestion list or the live catalog for 'openrouter-llm' — run Test model, or pick a listed one`. Errors are only the two rules above (syntax, secret-looking). Whether the id is "known" now consults, in order: the registry `models`, the workspace's cached live catalog for the credential home (any credential, fresh or stale), and the `provider_models` record (D-V4-24) — a tested-ok record within the tested window silences the warning.

**Every model-like field is a combobox.** The 27 `FieldSpec(name="model", type="string")` entries are retyped `type="model"` (no factory change: the kwarg name and value are unchanged; no config migration: stored `fields.model` values stay valid, `_validate_fields` still finds the field). `registry-form.tsx` renders `type="model"` with `ModelCombobox` (suggestions = the field's `options` if any, else none) and `ProviderSlotEditor` renders the model combobox for every kind in `MODEL_KINDS = {realtime, stt, llm, tts, image_gen, embedding}` **even when `models` is empty** (hint: "Type any id the provider accepts"). A registry test asserts no entry has both `fields[name=model]` and `models`, and that `type="model"` fields never carry `options` that contradict `default_model`. Rejected: moving the 27 onto `ProviderRef.model` (a config migration through `lkap_contracts.migrate` plus an unknown-field warning on every stored config until it runs).

### D-V4-24 — Model capabilities: declared → detected → catalog → registry → unknown, stored once per workspace, delivered to the worker

**Contract.** `ModelCapabilities(BaseModel)`: `vision: bool | None`, `tools: bool | None`, `audio_in: bool | None`, `audio_out: bool | None`, `streaming: bool | None`, `context_tokens: int | None`, `source: Literal["declared","detected","catalog","registry"] | None`. `None` means unknown. Additive; exported.

**Storage: `provider_models` (migration `v4_002_provider_models`, pre-authorised by R-V4-24).** One row per `(workspace_id, provider_home, model_id)` where `provider_home = credential_home(provider_id)` (so an OpenRouter model tested from the STT entry and the LLM entry is one row per kind — the row also carries `kind`). Columns: `id`, `workspace_id`, `provider_id` (the entry the test ran for), `provider_home`, `kind`, `model_id` (≤ 200), `declared` JSON (`ModelCapabilities` set by an admin), `detected` JSON (from the last probe), `last_test_at`, `last_test_ok`, `last_test_message` (scrubbed, ≤ 500), `last_test_latency_ms`, `last_test_cost_usd` (numeric, nullable), `last_test_credential_id`, `last_test_fingerprint` (the credential's fingerprint at test time), `catalog_seen_at`, `catalog_missing_since`, `created_at`, `updated_at`; unique `(workspace_id, provider_home, kind, model_id)`; index on `workspace_id`. Rehearsed up → down → up on a copy and on the Postgres CI job like `v4_001`; applied to the dev DB by the coordinator after a `.backup`. Why not elsewhere: `Credential.last_test_*` is per key, `ProviderCatalogCache` is per vendor list, `AgentConfig` would copy the same fact into every agent and lose it on a model change. Rejected: a JSON blob on `WorkspaceProvider` (no index by model, no per-row timestamps).

**Resolution (`lkap_api/custom_models/capabilities.py`).** `resolve_capabilities(spec, model_id, record, catalog_item) -> ModelCapabilities`: a field is taken from the first source that knows it — `record.declared`, then `record.detected`, then the live catalog item's meta (OpenRouter `architecture.input_modalities` ∋ `image` → `vision`, `supported_parameters` ∋ `tools` → `tools`; Anthropic `capabilities.image_input.supported`; Mistral `capabilities.vision`/`function_calling`; xAI `input_modalities`; Bedrock `inputModalities`/`responseStreamingSupported`; Gemini `supportedGenerationMethods` ∋ `bidiGenerateContent` → `audio_in`/`audio_out` for realtime; Fireworks `supportsTools`; ElevenLabs `can_do_text_to_speech`; OpenAI/Groq/Cerebras contribute nothing), then the registry `ModelSpec.supports_video` (→ `vision`) and `ProviderCapabilities.tool_calling` (→ `tools`), else `None`. `source` names the winning source for `vision`.

**Delivery.** `ResolvedProvider.capabilities: ModelCapabilities | None = None` (additive). `routers/internal.py::_build_resolved` fills it for the `llm`, `workflow_llm` and `realtime` slots. `platform_agent.model_vision_support` reads `resolved.capabilities.vision` first and falls back to `vision_support()`; `describe_current_frame` does the same. So a custom text-only model declared or detected as `vision=False` stops receiving image parts, and the validation warning (`_validate_modes`) fires on the resolved `False` rather than only on the registry's. Unknown stays unknown: the worker keeps today's optimistic path and the validator adds the untested-custom-model warning of D-V4-26.

**Declaring.** `PUT /v1/providers/{id}/models/{model_id}` `{declared: ModelCapabilities}` (admin, `providers:write`; the slot editor's "This model can…" toggles under the combobox for a custom id, saved with the agent form's Save through a small mutation, R-V3-2: inline, no drawer). MCP: `provider_model_declare` (Operator, `providers:write`).

### D-V4-26 — "Test model": one capped, real call from the api process, per-kind probes, stored per workspace, a warning when missing

**Where it runs.** The api process, over `HttpClientDep`/the guarded aiohttp session (net_guard, no redirects, DNS-pinned), never the worker: the worker has no inbound surface (§1.1), and the api already calls vendors for the judge and the embedder. Stated limitation: a passing probe proves *the vendor accepts this model id with this key and answers*; it does not prove the LiveKit plugin constructs it (a `Literal`-typed kwarg, a plugin-side rename). That gap stays with the first-session build path, which already reports `ProviderBuildError` per slot; the result panel says so in one line.

**Probe tree.** `ProviderSpec.probe: str | None` names a probe adapter in `lkap_api/custom_models/probes/` — a second tree, deliberately not folded into `test`: `test == catalog.adapter` is a documented invariant (a GET that lists), a probe is a POST with a payload and a budget. One adapter per wire shape, parameterised by `base_url`:

| kind | probe | what it sends | passes when | detects |
|---|---|---|---|---|
| llm | `openai_chat` (OpenAI, OpenRouter, Groq, Cerebras, xAI, Mistral, Together, Fireworks, `openai-compatible-llm`, LiveKit Inference via the gateway + project JWT), `anthropic_messages`, `gemini_generate` | `messages=[{"user": "Reply with the single word ok."}]`, `max_tokens=4`, `temperature=0`, `stream=false`; then, if `probes` includes `tools` (default on for llm), a second call with one tool `{"name": "ping", "parameters": {"type": "object", "properties": {}}}` and `tool_choice` forcing it (`required` / Anthropic `{"type": "tool", "name": "ping"}` / Gemini `functionCallingConfig.mode=ANY`); if `probes` includes `vision` (off by default), a third call with a 1×1 PNG data URL and `max_tokens=4` | HTTP 2xx and a non-empty text or a tool call; a 4xx naming the model (`model_not_found`, 404, "does not exist") → `ok=false` with the scrubbed vendor reason | `tools` (tool call came back → true; a 400/404/422 naming the tools parameter → false; a cut-off at the budget — `finish_reason=length` or a 4xx naming `max_tokens`/an output limit — or any other refusal → unknown, asks #60/#65), `vision` (2xx on the image call), `streaming` unknown; usage tokens → cost |
| stt | `openai_transcriptions` (OpenAI, OpenRouter, Groq), `deepgram_listen`, `elevenlabs_stt`, `cartesia_stt` | the bundled `probes/fixtures/ok_1s_16k.wav` (1.0 s, 16 kHz mono PCM, a voice saying "okay", ≈ 32 KB, generated and checked in) | 2xx and a transcript (any text) | `audio_in`; transcript sample |

Registry entries without a `probe` return `ok=None`, `message="no test for this provider; the model is checked on the first session"` and the validator's untested warning stays. An entry whose `probe` is set but whose kind is `vad`/`turn_detection`/`noise_cancellation` is a registry-test failure.

**Route.** `POST /v1/providers/{provider_id}/test-model` body `ModelTestRequest{model: str, credential_id: str | None, connection_id: str | None, fields: dict[str, str|int|float|bool] = {}, probes: list[Literal["basic","tools","vision"]] = ["basic","tools"], force: bool = false}`. `connection_id` matters only for `livekit-inference-*` (`requires_credential=False`, so `_resolve_credential` yields nothing): the probe signs the gateway JWT with that connection's key and secret through `ConnectionClientFactory`; when omitted, the workspace's default connection is used — the one `POST /v1/agents` would bind (`connections.default_for(workspace)`), else 422 `no LiveKit connection to sign the Inference request with`. The JWT is `AccessToken(key, secret).with_identity("agent").with_inference_grants(InferenceGrants(perform=True)).with_ttl(600 s)` from `livekit-api` (§1.2, verified against the installed SDKs); the record's fingerprint for Inference rows is the connection's key id. → `ModelTestResult{ok: bool | None, provider_id, model, kind, checked_at, cached: bool, latency_ms: int | None, probes: [ProbeResult{name, ok, latency_ms, message}], detected: ModelCapabilities, cost_estimate_usd: Decimal | None, cost_note: str, sample: str | None (≤ 200 chars, untrusted), record_id}`. Steps: `validate_model_id` (422 on failure, no echo) → resolve the credential like the catalog route (`_resolve_credential`, home-aware; for `livekit-inference-*` the agent's/workspace's default connection key and secret via `ConnectionClientFactory`) → the 10-minute per-`(workspace, home, kind, model, fingerprint)` result cache unless `force` (mirrors `credential_tests.CACHE_TTL_S`; a cached answer is returned with `cached=true`) → rate limit `RateLimiter.hit(f"test-model:ws:{workspace_id}", capacity=10, per_seconds=60)` (shared across replicas on Redis) and a **process-local** semaphore of 2 concurrent probes per workspace (the same honesty as `limits.slot_lock`: a Postgres deployment with `api ×2` allows up to 4; the token bucket is the cross-replica cap) (429 `rate_limited` with `retry_after`) → `net_guard.check_url` on any `base_url` field (422 `judge base_url refused`-style) → run the probe with `asyncio.wait_for` 15 s (llm), 20 s (stt/tts), 10 s (embedding/realtime/avatar) → upsert the `provider_models` row → audit `provider.test_model` with `{provider_id, model, ok, latency_ms}` (no secrets, no sample) → respond. Gating: a more specific rule `_Rule("/v1/providers/{provider_id}/test-model", read=Requirement("builder","providers:read"), write=Requirement("builder","agents:write"))` — the longest template prefix wins in `policy_for`, so builders can test the model they are configuring, exactly as test chat spends vendor money under `sessions:write`; declaring capabilities and reading another workspace's rows stay admin. `GET /v1/providers/{id}/models?custom=true&limit=` lists the workspace's rows (`ProviderModelOut`), `GET /v1/providers/{id}/models/{model_id}` one row (viewer, `providers:read`).

**Cost.** `cost_estimate_usd` = `pricing.lookup(provider_id, model, unit)` × the probe's usage when a price exists, else OpenRouter's `meta.pricing` from the cached catalog item (`prompt`/`completion` per token; a TTS probe's characters × `prompt`, with any `completion` price for output audio left out and named in the note, ask #66), else `None` with `cost_note="no price on file for this model; the probe used N tokens / M characters / 1 s of audio"`. Caps are by **count**, not dollars: 10 tests per workspace per minute, 2 in flight, `max_tokens ≤ 4`, TTS input ≤ 8 characters, STT clip 1 s, no image generation, `vision` probe opt-in. A workspace can turn the route off (`WorkspaceProvider`-level `providers.disabled` already blocks a provider; no new setting).

**Secrets.** Probes receive the decrypted bag and return only structured results. Every message that reaches storage, the response or a log is passed through `scrub(text, secrets.values())` (replaces each secret value and its first/last 6 characters with `•••`, then truncates to 500) — some vendor 401 bodies echo the header. Logs carry `provider_id`, `model`, `probe`, `ok`, `status_code`, `latency_ms`, `error_type` only (`kwarg_names`-style, as the factory does).

**Untrusted output.** `sample` (the LLM's word, the STT transcript, ≤ 200 chars) and any vendor `message` are data: the console renders them in a mono `<pre>`-styled box, never as markdown or HTML; the MCP wraps `sample` and `message` with `untrusted(…, f"test-model:{provider_id}")` as `provider_catalog` wraps labels; TTS returns byte count and content type, never bytes.

**Shown as.** The slot card and the slot editor show a chip next to the model: `Tested ✓ 2 min ago` (success, `last_test_ok` and the credential's fingerprint unchanged), `Test failed · <reason>` (danger), `Untested` (neutral, with a "Test" button; builders and admins), `No test for this provider` (neutral). The chip's "tested" window for **validation** is 30 days with the same fingerprint (`TESTED_WINDOW_S`), separate from the 10-minute re-run suppression: a rotated key resets the chip to Untested. Clicking Test opens an inline result panel under the combobox (latency, per-probe rows, detected capabilities, cost line, the sample in a mono box, and the "proves the vendor, not the plugin" line); the Providers page's Catalog dialog gets a Test column for catalog items (admin). Dialogs only (R-V3-2).

**Validation link** (`custom_models/validation.py`, registered through `config_service.register_validator` like `catalogs/validation.py`): for every slot with a model outside the registry list: `warning` `pipeline.<slot>: custom model '<id omitted>' has not been tested with this key — run Test model` when no ok record within the window; `warning` with the scrubbed reason when the last test failed; `warning` `… no longer appears in <vendor>'s catalog (last seen <date>)` from D-V4-27; and the vision warning from the resolved capability (D-V4-24). No new errors. `agent_publish` inherits these as warnings (the MCP's "test before you publish" rule already tells the agent to look). Strict mode (untested → error at publish) is deferred: recorded in R-V4-26 as a later workspace setting, not built.

### D-V4-27 — Keeping the registry current: a CI drift job, a promotion rule, deprecation warnings

**Drift job.** The logic lives in `lkap_api/catalogs/drift.py` (so its tests live in `api/tests/` under the api gate, like every other api module) and `scripts/catalog_drift.py` is a thin `uv run --project api python -m lkap_api.catalogs.drift` entry point. It uses the one adapter tree (`lkap_api.catalogs.adapters`, D-V2-9) and, for every `available` entry with a `catalog`, fetches page one with secrets from the environment (`SECRET_ENV_BY_HOME`: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`, `DEEPGRAM_API_KEY`, `ELEVENLABS_API_KEY`, `CARTESIA_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`, … — the names `live.yml` already declares plus new optional ones), applies the entry's `CatalogFilter`, and compares: `registry_not_upstream` (a `models[].id` or `default_model` the vendor no longer lists — the serious one), `upstream_new` (ids created after the newest registry entry's `created`/`created_at`, or simply not in the registry, capped at 25 per entry with a stable sort), `deprecation_notices` (OpenAI `shutdown_date`, Mistral `archived`, Bedrock `modelLifecycle`), `skipped` (no secret in the environment, or a vendor error — never a failure). Keyless entries always run: OpenRouter, Deepgram, Rime. Output: `catalog-drift.md` (artifact) and a JSON summary; the job **never fails the build**. Workflow `.github/workflows/catalog-drift.yml`: `schedule: cron "23 6 * * 1"` (weekly) + `workflow_dispatch`; `permissions: contents: read` at the top and `issues: write` on the one job that runs `gh issue create`/`gh issue edit` to keep **one** open issue titled `Catalog drift` (updated in place, labelled `registry`), the body being the markdown; secrets from repository settings like `live.yml`; the free-text dispatch input is data, never script (V2-21).

**Promotion rule (`docs/CONTRIBUTING`-level, recorded as R-V4-27).** A model becomes a registry `ModelSpec` when (1) the drift report or a user names it, (2) a `test-model` run passed on the dev stack with the id (the brief records provider, id, latency, cost, detected capabilities), and (3) the PR edits `providers.py` only (`models`, and `default_model` only with a second line of evidence: a text-chat session on the dev stack). `supports_video` flips to `True` only from a passing `vision` probe or a recorded vision session, never from vendor metadata alone (the existing `ModelSpec` rule). A `default_model` is never a `:free`, `auto` or preview id. `VERIFIED_IDS` is untouched by this process (that is a provider-level live call).

**Deprecation / disappearance.** (1) Explicit signals: when a live catalog item carries `shutdown_date`/`archived`/`modelLifecycle.status ∈ {LEGACY, …}`, `service.get_catalog` writes `catalog_missing_since = <the date>` (or now for `archived`) on every `provider_models` row of that workspace/home/model and the validator warns `deprecated by <vendor> on <date>`. (2) Disappearance: on every successful catalog fetch the service marks `catalog_seen_at = now` for rows whose id is in the new list and sets `catalog_missing_since = now` (if unset) for rows that **were in the previous cached list of the same entry and filter** and are not in the new one — a comparison is sound only against the same filtered list, so `openrouter_llm_models` (tools filter) never flags non-tool models. A registry `ModelSpec` is compared the same way by the drift job, not at request time. The warning clears when the id reappears. Rows never touched by a catalog (vendors without a list) never get the warning.
