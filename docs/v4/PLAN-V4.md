Naming: v4 packages are **`V4-nn`**. Rulings are **`R-V4-n`** (§5) and amend the cards, `TEMPLATES.md`, `OPENROUTER.md` and `PHONE-NUMBERS.md`. Design: [`TEMPLATES.md`](TEMPLATES.md) (decisions D-V4-1…8, contracts, seeding algorithm, the catalogue, the dialog, tests); [`OPENROUTER.md`](OPENROUTER.md) (findings per modality with sources, decisions D-V4-9…13, the live check); [`PHONE-NUMBERS.md`](PHONE-NUMBERS.md) (LiveKit-hosted numbers: facts from the upstream proto and the `lk` CLI, decisions D-V4-14…22, the shim, the live check); [`CUSTOM-MODELS.md`](CUSTOM-MODELS.md) (custom model ids, live catalogs per vendor with sources, the "Test model" probes, the drift job, decisions D-V4-23…28, the live check); [`BACKGROUND-TOOLS.md`](BACKGROUND-TOOLS.md) (what `livekit-agents 1.8.2` already does for async tools, verified by file and line; the per-tool execution policy, the safety rule, the wrapper, composition with realtime/text/flows, decisions D-V4-29…38, the live check). V4-06 (populate-and-validate) has no design doc; its card is the whole spec.

Definitions (unchanged from `../v3/PLAN-V3.md`):
- **Python gate** (inside the package dir): `uv run ruff check . && uv run ruff format --check . && uv run mypy src/ --strict && uv run pytest -q -m "not live"`.
- **Web gate** (in `web/`): `pnpm lint && pnpm typecheck && pnpm test` (never `pnpm build` in `web/`; HANDOFF rule 6).
- **Contracts gate**: `cd contracts && uv run python -m lkap_contracts.export && cd .. && scripts/export_contracts.sh && git diff --exit-code contracts/generated web/src/contracts mcp/src/lkap_mcp/generated mcp/claude-plugin/skills/lkap/recipes`.
- **Exclusive ownership**: a package edits only the paths its card lists; anything else is a one-line ask in `docs/v4/_asks.md` (V4-01 creates it with the v3 format: **owner package** — file — the exact edit — who asked — status). The coordinator's decisions there are binding.
- **Migration discipline** (HANDOFF rule 4): none in V4-01…V4-04 (D-V4-3: no new column). V4-05 carries **one**, `v4_001_livekit_numbers`, pre-authorised by R-V4-11: rehearsed on a copy and on the Postgres CI job, applied to `api/data/lkap.db` by the coordinator after a `.backup`. V4-07 carries the **second and last**, `v4_002_provider_models`, pre-authorised by R-V4-24 under the same rehearsal discipline. Any other package that finds it needs one stops and files an ask.
- **Live rules** (HANDOFF rule 3): a scratch api on its own port and DB, a worker under a fresh agent name, never `lkap-agent`, never `other-project-agent`.
- **Path rules**: never create, read or name a path whose segment starts with `credentials` (HANDOFF rule 1) — say "provider keys", `provider_keys.py`, `/console/keys`; never read or write `.env*` (rule 2). The catalogue's prose names only fictional companies and `example.com` (R-V3-8).

## 4. Risks

- **`seed_config_from_manifest` assumptions.** It reads `manifest.default_panel` only through `effective_layout` (the config's `panel` stays default). Templates that compose blocks must store them (§4 step 2) or block tools will not register. Mitigated by the flow-reference test, which fails if `request_form`/`table_append` are not allowed for `receptionist`.
- **Placeholder tool URLs** on `receptionist`: an unedited starter reports "couldn't reach the booking system" at runtime. Accepted (R-V4-4); the next step and the dry run make the fix one edit.
- **Long JSON flows** are easy to break by hand. The test validates every one; the MCP `agent_flow_validate` recipe covers edits after creation.
- **Console before api**: a console upgraded before its api sees a 404 on `templates`; the fallback to `packs` keeps the dialog working with derived tiles.
- **Two "Acme"s** in seeds (dental practice, meter product) are fictional by design; the doc lint keeps real hostnames out.
- **LiveKit's rule-conflict refusal** (V4-05): the shared project hosts `other-project-agent`'s rules, which LKAP cannot see. Mitigated by the pre-check warning and the 422 relay that names LiveKit's message; the live check records the outcome.
- **Unverified LiveKit semantics** (V4-05 §1: the grant, detach, delete-while-attached, region): the design plans for both outcomes of each; the live check settles them; none changes the schema.
- **The demo run writes to the user's database** (V4-06): bounded by the Builder key, the `Demo — ` prefix, the manifest check after every run, one permitted delete, and the before/after diffs. A foreign write stops the run.
- **A probe proves the vendor, not the plugin** (V4-08): a model id the vendor accepts can still be rejected by the LiveKit plugin (a `Literal` kwarg, a plugin-side rename). Mitigated by the result panel's one-line caveat and the unchanged first-session `ProviderBuildError` path; a worker-side build check is a later decision (R-V4-25).
- **Vendor list shapes drift** (V4-07): three adapters already disagree with today's vendor pages (Cartesia headers, Hume `provider`, ElevenLabs v1/v2). `parse_items` stays lenient, page one is always tried, and the live check settles each; none may fail the providers page (V2-06 rule).
- **Secret-looking ids** (V4-07): the prefix list is a heuristic; a key with an unknown prefix passes the id rule and is sent to the vendor as a model id — the vendor 4xx names it, and the scrub step removes the stored secret values from every message, so the exposure is one log-free vendor request. The list grows by test, never by guess.
- **Test-model cost** (V4-08): capped by count (10/min/workspace, 2 in flight, ≤ 4 tokens, 1 s of audio, no images), not by dollars, because most custom models are unpriced (`pricing.lookup` → `None`). Free-tier keys can still hit vendor rate limits; the 429 is relayed as `ok=false`, never retried.
- **Deprecation false positives** (V4-10): "missing from the live list" is compared only against the previous fetch of the same filtered list; explicit vendor signals are trusted as-is. A wrong warning is still a warning (never an error).
- **The SDK's async-tool surface is young** (V4-12): `RunContext.update`/`with_filler`, `ToolFlag`, `MCPToolset` and `ToolExecutionUpdatedEvent` are in 1.8.2 but appear in no release note and no shipped example; `AsyncRunContext` was renamed within a release. Mitigated by the tripwire test, the one-warning degradation to `blocking`, and by keeping every SDK call inside `tools/execution.py` and `declarative.py`.
- **Two background mechanisms** (V4-12): the pack `BackgroundRunner` (urgent interrupts) and the SDK executor (queued replies) coexist; both feed the same activity block under different `source`s. Merging them is a later ask, not a v4 goal.
- **The OpenRouter STT/TTS unit is inferred** (V4-15): `/models` documents no unit for speech models; per-second and per-character were derived by arithmetic against Deepgram's own page. A wrong map would mis-price live OpenRouter speech lines by ~60×; the live check's step 6 is the tripwire and the table row is the fallback (an ask, not a patch).
- **LiveKit's machine-readable prices are unofficial** (V4-15): the RSC payload can change shape without notice; it feeds the drift report only, is parsed leniently, and a failure is one skipped row. The HTML page stays the source of the table rows.
- **Participant minutes × 2 and the 10-second minimum are LKAP's reading of LiveKit's billing page** (V4-15): LiveKit did not confirm whether the agent participant is metered; the row carries a `tier_note`, and the first Cloud invoice after go-live is the check (recorded as an ask if it differs).
- **The snapshot runs off the creation path** (V4-15): a sub-second session can end before its background estimate lands and shows "no estimate"; accepted (rare, honest) rather than blocking the token endpoint.
- **Plan-based vendors stay unpriced until an admin types a number** (V4-15): ElevenLabs, Cartesia direct, Hume and every avatar vendor show "no price" out of the box; the "Set a price" affordance is the mitigation, and a workspace price is USD and dated so it is never mistaken for a list price.
- **A handoff can still be dropped on 1.8.2** (V4-14): #7321 is pre-existing for flows with any slow sibling tool; the flow-node downgrade limits the new exposure to zero until the bump, and the bump's live check exercises exactly that case.

IDs `R-V4-n`, recorded here so they outlive the chat. They amend the cards and `TEMPLATES.md`.

### R-V4-1 — Starters are configuration on a pack; packs stay code (user decision, 2026-09-24)
- The user's rule: insurance was one use case, not the starter pack. The gallery lists **starter templates**, data-only presets on the `generic` pack (`TEMPLATES.md` D-V4-1), and code packs appear only through a template (`insurance_claim`, category "example", last). No new code pack is created for a starter; a starter that needs code is a pack plus a template that names it.

### R-V4-2 — The New agent flow is a dialog; `UI_UX_SPEC.md` §4.2 is amended
- §4.2's "a page, not a modal" is withdrawn. The flow is a `Dialog` (`size="xl"`) opened from every "New agent" trigger; `/console/agents/new` stays as a deep link that opens the dialog over the agents list (`?template=` preselects). R-V3-2 (no drawers or sheets) applies unchanged. V4-02 replaces §4.2's text with a pointer to `TEMPLATES.md` §6.

### R-V4-3 — No template column, no migration; `pack_id` alone is the pack's derived starter
- `AgentCreate.template_id` is resolved at create time and remembered only in the version note and the log. When `template_id` is present, `pack_id` is ignored (it defaults to `generic` and the MCP tool always sends it; a "differs → 422" rule would reject every MCP create from a code-pack starter). `POST /v1/agents` with `pack_id` and no `template_id` keeps working and is defined as creating from the derived `pack:<id>` starter, so both paths run one seeding function. A column is Phase 2.

### R-V4-4 — Seeding gates, never fails, and ships no transfer targets
- A starter must create on any workspace: `capabilities.dtmf` is set only when the connection reports SIP, `recording.enabled` only when Egress and a storage config exist, and the catalogue ships **no** `telephony.transfer_targets` (the dialing policy is workspace state, R-V2-23). Placeholder HTTP tool URLs on `example.com` are allowed in the catalogue; they fail as ordinary tool errors until edited. The console explains what was gated in the create toast by comparing the starter with the created config; the api response shape does not change.

### R-V4-5 — The catalogue is tested, not trusted
- `api/tests/test_templates.py` pins the id list and derives every claim the gallery makes (required keys, vision model, tool references, block configs, seed files) from the contracts and the registry. A malformed catalogue entry is a startup error, not a skipped entry. The MCP doc lint resolves template ids in recipes against the live catalogue.

### R-V4-6 — Templates live in the api package; the MCP reads them live
- Models in `lkap_contracts`, data under `lkap_api/templates/catalog/`, served by `GET /v1/templates`; the MCP's `lkap://templates` is a live read like `lkap://packs`. No export-script copy of the catalogue; recipes reach the plugin through the existing copy step (G4).

### R-V4-7 — One vendor key may serve several registry entries: `credential_provider` (2026-09-25)
- A `ProviderSpec` may name another entry as its **credential home**; a credential row is stored under the home and every lookup (validation, seeding, catalog fetch, default-credential setting, key listing, template key requirements, the console picker) compares against `credential_home(spec)`. The home must exist, have no home of its own and declare the same secret field names. V4-03 sets it only on the four non-LLM OpenRouter entries (home `openrouter-llm`). Existing multi-entry vendors (OpenAI, Google, Deepgram, ElevenLabs, Cartesia) are not migrated in v4 — merging their existing rows needs a data migration and is an ask, not a side effect. Rejected: per-vendor key rows the user pastes N times (what the user asked to avoid), and a kind-less "vendor key" entry (invisible to the per-kind pickers).

### R-V4-8 — What OpenRouter may fill, and the honest defaults (`OPENROUTER.md` §1)
- OpenRouter fills `llm`, `workflow_llm`, `qa_llm` (worker and api-process judge), flow node LLM overrides, `stt`, `tts`, the KB embedder and `image_gen`. ### R-V4-29 — A flow that scopes no knowledge base searches all of the agent's; the console shows each step's effective scope (asks #27 / B-2, 2026-09-25)

(N from `config.knowledge.kb_ids`; N = 0 keeps today's "Attach knowledge bases to the agent first (Knowledge section)."); (2) the flow scopes something and this step's effective list is non-empty → read-only chips "From Global: <name>" ahead of the step's own picks; (3) the flow scopes something and this step's effective list is empty → "This step searches no knowledge base." Never an error (an author may attach a KB for a later step).

### R-V4-31 — The bare-token rule stays an error for model ids and becomes a warning for id-like fields; prefixes stay an error everywhere (ask #49, 2026-09-25)
- **The risk is real and the ask's fix is too blunt.** A vendor whose genuine avatar or voice ids are 32-hex strings would hit an `error` with no override and a message ("looks like an API key") that is wrong for them: the vendor becomes unusable. But dropping the bare-token rule from `avatar_id`/`face_id`/`pal_id`/`persona_id`/`voice*` removes the check exactly where a Simli- or Tavus-style 32-hex **key** is most likely to be mispasted (R-V4-21 chose the 32 threshold for them).
- **Decision: split by what the field is, not whether the rule runs.**
  - `SECRET_PREFIXES` matches → `error`, on every field, unchanged: a prefixed value is never an id.
  - Bare token (≥ 32 characters of one class, no separator) on a **model id** — `ProviderRef.model`, every `type="model"` field, `_checked_model_id` on the `/models/{model_id}` routes, `ModelTestRequest.model` — → `error`, unchanged: no real model id anywhere is one (`test_model_ids.py` proves it for the registry; fine-tune, Fireworks and OpenRouter ids all carry `:`, `/` or `-`).
  - Bare token on an **id-like field** — `ID_LIKE_FIELD_NAMES` and every `type="catalog"` field — → `warning` at the field path, value-free: "field 'face_id': the value looks like an API key; if it is the vendor's id, ignore this". The agent saves. The console mirror (V4-09) shows the same line inline and blocks nothing; the model combobox's Custom row stays disabled on a bare token, as designed.
  - Syntax failures (whitespace, `://`, forbidden characters, length) → `error` everywhere, unchanged.
- **Shape.** `validate_model_id(value)` keeps its signature and behaviour (it is the model-id rule). `lkap_contracts.providers` gains `validate_id_value(value) -> IdIssue | None` with `IdIssue(severity: Literal["error", "warning"], reason: str)` — in this order: prefix → error, **the syntax checks → error, then** bare token → warning (syntax before the token check, because `_BARE_TOKEN_RE` admits base64 `=` padding while `=` is a forbidden character: a padded key must stay an error, and every reason is value-free so the order costs nothing on echo) — and `custom_models/validation.py` uses it for the id-like/catalog fields. `ModelIdRules` is **unchanged** (no schema churn): which rule applies is a property of the field the console is rendering (`type="model"` vs `type="catalog"`/id-like), so `web/src/lib/model-ids.ts` (the V4-09 card's file) exposes `validateModelId(value, {field: "model" | "id"})` and its tests carry the split.
- **Stated cost.** A vendor with real 32-hex ids gets a permanent warning on that field until a registry opt-out exists (a `FieldSpec` flag that says "ids here are bare tokens"). That opt-out is filed as an ask by V4-08, not designed here: no such vendor is in the registry today.
- **Amends** R-V4-21 ("`validate_model_id` refuses only two things, as errors" now reads "…for model ids; on id-like fields the bare-token half is a warning, R-V4-31") and `CUSTOM-MODELS.md` D-V4-23 item 1.
