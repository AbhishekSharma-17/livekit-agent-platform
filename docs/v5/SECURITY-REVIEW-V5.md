## 1. Executive verdict

**Sound for supervised local use. Three groups of fixes before waves 7 to 11 build on it.** The integrations wave was built the way the plan asked. Both OAuth-style callbacks are single-use, constant-time, expiry-bound and verify the vendor side before a row is written. Every outbound call the api makes on behalf of an admin goes through `net_guard` and never follows a redirect. The Composio key can only ever be sent to Composio (three independent pins: the binding rule at save, the provisioning check on the returned MCP url, the worker's host pin and constant execute base). Caller uploads are sniffed twice, capped four ways and stored under server-generated keys with HKDF-signed, expiring, workspace-bound links. The timezone attribute is minted only inside the server-signed token. The tenant rule (`TENANT_TABLES` + `lkap_cross_workspace`) held on every new table. No secret, token, code, state or pasted key reaches a log line, an audit row, a response or a URL in the api and worker code. The proxy's access log, which keeps every query string, is S5-32.

What must change before the gate opens (all in V5-27, §6):

1. **Two denial-of-service holes a Builder can open with one file** (S5-1, S5-2): a zip-bomb `.docx` through MarkItDown (measured: 306 KB → +660 MB RSS, ~1000:1) and a quadratic regex in the chunker (a 1 MB heading line ≈ 3 hours of CPU). Under the default inline jobs backend they take the api down. Under `arq` they take ingestion down for every tenant.
2. **Consent integrity** (S5-3, S5-4, S5-5): the browser can rewrite the wording that gets hashed (so the hash no longer proves what was shown), the model can record a "tap" that never happened (a prompt-injection path to starting Egress), and a withdrawn consent does not stop a running recording.
3. **Untrusted content reaches the model unframed** (S5-6): KB chunks, connected-app results (email bodies, tickets), MCP and HTTP tool results are handed to the LLM as plain text. Only `describe_asset` and the lkap-mcp server frame them. One helper, applied at four sites, closes the platform's largest prompt-injection surface.

4. **The Apps admin gate has a side door** (S5-40, S5-41): a Builder (including the default Builder API key an AI coding agent holds) can turn on a tool finder, review destructive actions and enable caller sign-ins through the agent config, which the Apps routes reserve for admins, and a caller-initiated sign-in under the workspace subject may make one caller's account reachable from the next caller's session (unverifiable offline, so it fails closed until the live check).

Then the Composio and MCP hardening rows (S5-7 … S5-14), each small, and a set of Lows that are one-line fixes with a pinning test. The residuals (§7) are design choices recorded as rulings, hazards that belong to V5-16/V5-30, and multi-tenant concerns a production plan owns.
