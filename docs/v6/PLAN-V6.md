# LKAP v6 — master plan: speech that streams, LiveKit Inference everywhere it can go, a generic notebook and canvas, tools and kits for any use case

Status: **planned** — written by Fable 5.1 on 2026-09-28 against `main` at `3bd9cb8` (V5 closed by R-V5-19; the api test suite now runs under pytest-xdist). This plan turns the user's four asks of 2026-09-28 and the six v6 research documents (`docs/research-v6/`) into sequenced packages the coordinator runs autonomously: Fable decides, Opus and Sonnet implement, about 3–4 agents at a time, one commit and push per package. Every open question is answered here with a **default** (§1); the user can override any of them later by a ruling, and the affected card says what changes. Anything the research could not verify is a **spike** or a "verify at implementation" line, never an assertion.

Naming: packages are **`V6-nn`**, decisions **`D-V6-n`** (§1), rulings made while the plan runs **`R-V6-n`** (§7, appended by Fable). Cards are in §3, the security checkpoint in §4, what the user must provide in §5, the status table in §6.

The four asks, in one line each, with where the answer is:

1. *OpenRouter STT/TTS felt laggy.* They are request/response (one WAV per utterance, one POST per sentence), so they cannot be live-call speech; use OpenRouter for the LLM family only; the "no price" in the picker is two bugs — §1 D-V6-1, D-V6-2, D-V6-9; V6-01, V6-02, V6-03.
2. *LiveKit Inference: independent? pay-as-you-go? from a self-hosted server?* A LiveKit Cloud project feature that needs no room and bills pay-as-you-go over monthly credits; officially "N/A" for self-hosted, technically plausible with a separate Cloud project's keys — §1 D-V6-10 … D-V6-14; V6-04 (spike), V6-05, V6-09.
3. *A generic notebook with handwriting and sketching; more panels.* A `notebook` block, an ink `canvas`, a `layout` block, the generic primitives the insurance pack kept to itself, then signature, chart, timer, code and cart — §1 D-V6-15 … D-V6-21; V6-06, V6-08, V6-10, V6-12, V6-14, V6-23, V6-24.
4. *Tools for any use case, as rich as the insurance pack.* Context placeholders, result bindings, live extraction with declarative rules, datasets, a flow `tool` node, and tool **kits** — §1 D-V6-22 … D-V6-28; V6-07, V6-11, V6-13, V6-15, V6-16, V6-17, V6-18, V6-19, V6-22.

## 0. Ground rules, prerequisites and ownership

### 0.1 Rules (the v5 set stands; restated where v6 adds to it)

Everything in `docs/v5/PLAN-V5.md` §0.1 applies unchanged: the Python, Web and Contracts gates; exclusive ownership with one-line asks in `docs/v6/_asks.md`; the live rules (a scratch api on its own port and database, a worker under a fresh agent name, a Builder key minted for the run and revoked after, `Demo — ` objects only); the path rules (never a path segment starting with `credentials`, never `.env*`, fictional companies and `example.com` only, no user names, machine paths, real hostnames or key values anywhere in the repository); the UI rules (dialogs only, never a drawer or sheet; no internal jargon in a string the user sees; mobile at 375 px with no horizontal page scroll; axe green on every new dialog); the compatibility rule (a new config field never changes what an existing published agent does, pinned by a test per package); the contracts rules (additive `__init__`/`export.py` edits, generated files never hand-merged, contracts commits serialised within a wave); the new-block rule (R-V5-7: a contracts package that adds a `BlockType` member also adds the minimal web entries so the parity and fixture tests stay green from the contracts commit); the MCP docs lint rule; the commit rule (one commit per package, the attribution line from the session reminder, pushed to `origin`).

Added in v6:

- **Untrusted content is fenced** (R-V5-15): every new site that hands third-party or caller text to the model — dataset rows, bound tool results read back through `describe_panel`, caller edits of a block, handwriting read from a canvas snapshot, kit instruction snippets are *not* untrusted (admin-authored) — calls `fence(text, source=…)` and joins `FENCED_SITES`, with the parity test updated in the same commit.
- **`net_guard` on every outbound call** the worker or api makes for a new tool kind (datasets are api-local; kits instantiate HTTP tools that pass the existing host checks); a placeholder never lands in a URL's scheme or authority (D-V6-22).
- **No secret in a log line, an event payload, a brief or a test fixture**: the new inference credentials (D-V6-11) follow the connection key pair exactly (`*_ct` columns, a fingerprint, placeholders in `redacted_env`); tests use `…-placeholder-…` values, never a vendor-shaped key (S5-45).
- **Migration rehearsal and backups** (§0.3): `upgrade head → downgrade <previous> → upgrade head` on a copy of the dev database and on the Postgres CI job, logged to `docs/v6/_briefs/migration-rehearsal-v6.md`; the coordinator applies after `sqlite3 api/data/lkap.db ".backup <scratchpad>/…"`, never a package.
- **Tests are xdist-safe**: since `3bd9cb8` the api suite runs one Postgres database per worker; a new test never binds a fixed port, a fixed file name under a shared directory, or a module-level singleton another test could observe.
- **Plain wording in UI copy and docs**: say "Streams while it speaks" / "Waits for the whole sentence", "Handwriting", "Drawing board", "Lookup table", never "WS", "SSE", "PCM", "JSON pointer" in a string the user sees.
- **Shared hot files.** `api/src/lkap_api/config_service.py` (validators), `contracts/src/lkap_contracts/tools.py` (tool constants and definitions) and `agent/src/lkap_agent/platform_agent.py` are named by several cards. The **hunk each card names is granted by this plan** (the R-V5-1 pattern: a package edits only the function or constant its card lists and nothing else in the file); within a wave the coordinator merges those hunks in the listed start order and the later package rebases over the earlier one. A card that needs more than its named hunk files an ask.

## 1. Decisions (defaults for every open question)

Each decision: **default** → rationale. "Override" says what a later ruling would change. Groups: S = speech vendors and gateways (`openrouter-audio.md`, `speech-vendors.md`, `tts-vendors.md`, `gateways-audio.md`), I = LiveKit Inference (`livekit-inference.md`), P = panels (`panels-and-tools.md` §1, §2 items 8–9), T = tools (`panels-and-tools.md` §2 items 1–7), X = cross-cutting.

### Speech vendors and gateways (S)

- **D-V6-1 OpenRouter is the LLM family, not the voice.** Default: `openrouter-llm` (and through it `workflow_llm`, the QA judge, `openrouter-embedding`, image generation) stays a first-class choice; `openrouter-stt` and `openrouter-tts` stay in the registry, flagged non-streaming (D-V6-2) and labelled "Waits for the whole sentence — not for live calls" in the console; the api validator emits a **tip**, not an error, when a voice pipeline uses either. Rationale: the research verified both endpoints are request/response (`docs/research-v6/openrouter-audio.md`), LKAP wraps them in `StreamAdapter`s (one WAV per utterance, one POST per sentence), and the measured first-audio time was 2–4 s against about 0.7 s p50 on LiveKit Inference; they remain useful for text tests, batch work and voice comparison. Override: a ruling could hide them from the voice pickers entirely.
- **D-V6-2 Streaming is a registry capability.** Default: `ProviderCapabilities.streaming: bool | None` for `stt` and `tts` entries (`None` = not recorded; the console says nothing), set from the plugin's `STTCapabilities`/`TTSCapabilities` flags at livekit-agents 1.8.3 and recorded per entry with a `note` when it depends on a field (`openai-stt` streams only with `use_realtime`; `rime-tts` only with `use_websocket`; `google-tts` only with a Chirp 3 HD voice). Non-streaming today: `openrouter-stt`, `openrouter-tts`, `openai-tts`, `azure-tts`, `speechmatics-tts`, `hume-tts`, `groq-stt`, `groq-tts`, `fal-wizper-stt`. Rationale: today the only signal is prose in `notes` (`contracts/src/lkap_contracts/providers.py:1380-1427`) and the per-model `ModelCapabilities.streaming` (an LLM probe result), so the console cannot chip it and the validator cannot warn. Override: none needed.
- **D-V6-3 Recommended voice stack.** Default: on a **LiveKit Cloud** connection the recommended stack is LiveKit Inference as today (`deepgram/nova-3`, `google/gemma-4-31b-it`, `inworld/inworld-tts-2`; both packs already seed it), shown as "Recommended" in the pickers and pre-selected in the create dialog; on a **self-hosted** connection the recommended stack is direct keys that stream end to end: Deepgram Nova-3 (Flux as the low-latency option, D-V6-5) with Cartesia Sonic (ElevenLabs Flash and Deepgram Aura-2 as the alternatives). No multi-model gateway is recommended for audio. Rationale: `speech-vendors.md` and `tts-vendors.md` list which plugins stream; `gateways-audio.md` found no gateway with a streaming LiveKit plugin. Override: a Together AI plugin (D-V6-7) would add a one-key alternative.
- **D-V6-4 Defaults that change, and how.** Default: (a) plugin defaults the vendor has **deprecated** are corrected in the registry — `inworld-tts` `inworld-tts-1.5-max` → `inworld-tts-2`, `minimax-tts` `speech-02-turbo` → `speech-2.8-turbo` — and the old id stays in `models[]` with `note="deprecated by the vendor"`, so a stored ref that names it still resolves and the validator says so; (b) newer defaults where the old model still works — `cartesia-tts` `sonic-3` → `sonic-3.6`, `elevenlabs-tts` `eleven_turbo_v2_5` → `eleven_flash_v2_5` — change `default_model` only, which touches only refs stored without a model (every pack and template writes the model explicitly); (c) **behaviour switches** are new `FieldSpec`s that default to the plugin's current behaviour, so no stored agent changes: `openai-stt.use_realtime` (off), `rime-tts.use_websocket` (off), `elevenlabs-tts.output_format` (the plugin's), `minimax-tts.audio_format` (the plugin's); the api validator emits a tip naming the streaming value, packs and starter templates seed the streaming value for new agents, and the console pre-selects it. Rationale: the compatibility rule of §0.1; the coordinator asked for "default to realtime, or warn" and the rule chooses warn-plus-seed. Override: a ruling after the V6-03 live check may flip (c) to on for everyone, with a note in the RUNBOOK.
- **D-V6-5 Deepgram Flux gets its own entry.** Default: `deepgram-flux-stt` on `livekit.plugins.deepgram.STTv2` (models `flux-general-en`, `flux-general-multi` — verify the second against the 1.8.3 plugin), capability `end_of_turn=True` (new; means the transcriber decides turn ends), and `session_builder` passes the SDK's "turn detection by the STT" setting when the STT entry declares it (verify the exact option name against 1.8.3 before pinning; the tripwire test pins it). `deepgram-stt.models` drops `flux-general-en` (today listed under the wrong class, `providers.py:945-949`) with a note pointing at the Flux entry; a stored ref naming it gets a validator error with the fix. Rationale: `speech-vendors.md` — Flux is a different class with built-in end-of-turn. Override: none.
- **D-V6-6 Fireworks STT is retired.** Default: `fireworksai-stt` → `availability="removed"` (the mechanism exists, `providers.py:44`, `:3485`); hidden from pickers; an agent naming it gets a validator error "Fireworks stopped its speech service on 2026-06-10; pick another transcriber". Rationale: `gateways-audio.md`. Override: none.
- **D-V6-7 Other gateways.** Default: no new audio entries for fal, Groq, DeepInfra, Replicate, AI/ML API or Eden AI (batch, or no LiveKit plugin); the existing `groq-stt`, `groq-tts` and `fal-wizper-stt` are flagged non-streaming and Groq TTS notes its 200-character cap. **Together AI** is the one gateway with documented streaming STT and TTS and no plugin; a custom `together-stt`/`together-tts` plugin is an **unscheduled spike** that starts only by ruling when the user supplies a Together key (§5). Rationale: `gateways-audio.md`. Override: the ruling.
- **D-V6-8 LiveKit Inference catalogue refresh.** Default: V6-02 rewrites the three `livekit-inference-*` model lists to the current docs table (`docs/research-v6/livekit-inference.md` §3): STT adds Deepgram Flux multi, Nova-3 Medical, AssemblyAI Universal-3.6 Pro Streaming, Cartesia Ink 2, Speechmatics Linden-1 and xAI `stt-2`; LLM adds the current Gemini 3.x Flash, GPT-5.x, Grok 4.x and DeepSeek V4.1 Flash ids and drops deprecated ones; TTS adds Cartesia Sonic 3.6, Deepgram Flux TTS, Fish Audio S2.1 Pro, Gradium, Inworld TTS 2 Flash, Rime Coda and xAI `tts-1`. **The implementer verifies every id against the docs page on the day and adds none it cannot verify**; the voice list stays a short curated list per model (LiveKit publishes no voice catalogue; a voice adapter is out of scope). `inference.realtime` models (undocumented) and ElevenLabs (never in LKAP's list; two research documents disagree on its status) are not added. Rationale: the 1.8.3 `Literal`s are type hints and the gateway's catalogue decides; the registry is behind. Override: none.
- **D-V6-9 The two pricing defects.** Default: **A** — `load_live_sheets` (`api/src/lkap_api/costs/prices.py:171-219`) selects only `credential_id IS NULL` cache rows unless a ref carries a `credential_id`; the picker route passes bare `(provider_id, model)` pairs (`routers/costs.py:206-257`), and every OpenRouter catalogue row is keyed, so no OpenRouter model ever gets a price. Fix: derive the unit per catalogue item (per-second, per-token or per-character) from the item's `architecture`/pricing keys, price token-billed speech through the existing token branch of `estimate.py`, price Gemini TTS audio-out from `audio_output`, and refuse an implausible figure (STT above $1 per audio minute, TTS above $1 per 1,000 characters) as "unit unknown — no price" rather than show a wrong number. Reconcile (`jobs/reconcile.py`, LLM only) extends to STT/TTS generation ids where the worker reports them. Rationale: `openrouter-audio.md` reproduced A in memory and named B's examples. Override: none.

### LiveKit Inference (I)

- **D-V6-10 Facts this plan relies on** (all from `docs/research-v6/livekit-inference.md`, verified against the SDK source and LKAP's code; none tested live): Inference is a **LiveKit Cloud project** feature — the SDK mints a JWT from `LIVEKIT_INFERENCE_API_KEY/SECRET`, else `LIVEKIT_API_KEY/SECRET`, and sends it to `agent-gateway.livekit.cloud` whatever `LIVEKIT_URL` says; **no room is needed** (LKAP's model "Test" button already calls the gateway with no room); billing is **pay-as-you-go on top of monthly credits** (Build $2.50 as a hard cap, Ship $5, Scale $50, then list prices; STT by seconds, LLM by tokens, TTS by characters; zero data retention by default); the self-hosting comparison table says "Built-in inference: N/A" for self-hosted. In LKAP today a self-hosted connection is hard-wired to `inference_available=False` (`api/src/lkap_api/connections/probe.py:66-67`), the worker env carries no `LIVEKIT_INFERENCE_*` (`connections/bundle.py:68-88`) and the factory strips key kwargs from Inference providers (`agent/src/lkap_agent/providers/factory.py:117-124`).
- **D-V6-11 Self-hosted servers may use Inference through per-connection "LiveKit Cloud Inference credentials".** Default: a self-hosted connection may store the key pair of a separate LiveKit Cloud project (encrypted like the connection's own pair, `v6_001`), which the pool receives as `LIVEKIT_INFERENCE_API_KEY/SECRET` (the SDK reads them first, so no worker code changes; the factory invariant "credentials are kwargs, never env" is unchanged because the worker pool is per connection); `inference_available = use_inference and (cloud or has_inference_credentials)`; the turn detector stays `local` on self-hosted; the api's gateway calls sign with the inference pair when present and refuse on self-hosted without one; the connection test mints a token and makes the cheapest authenticated call (a one-token chat on the default LLM — there is no documented free endpoint). The UI says, in plain words: "LiveKit says Inference is for LiveKit Cloud projects and does not support it with a self-hosted server. This uses a separate Cloud project's keys; usage is billed to that project and travels over the public internet." **Gated** by D-V6-12: V6-05 and V6-09 start only after R-V6-1 records "works"; if the spike fails they are cancelled and the console keeps today's message. Override: a LiveKit statement that this is unsupported use under their terms cancels the feature regardless of the spike.
- **D-V6-12 The spike is a package of its own** (V6-04, S-sized, no product code). Default: a scratch script in the session scratchpad runs `inference.STT/LLM/TTS` and a `WarmTransfer`-free agent against a local `livekit-server --dev` with a **free Build project's** key pair in `LIVEKIT_INFERENCE_*`, records whether the gateway accepts JWTs whose room and job headers name a foreign server, the observed latency, and what the Build console shows afterwards; the brief `docs/v6/_briefs/v6-04-spike.md` records the verdict and Fable writes it as **R-V6-1**. The brief also names the terms-of-service question for the user to raise with LiveKit. Rationale: the research says "probably works, undocumented"; the plan does not build on "probably". Override: none.
- **D-V6-13 No shared workaround.** `LKAP_SUPERVISOR_PASSTHROUGH_ENV=LIVEKIT_INFERENCE_API_KEY,…` is not documented as a path: it is shared across every pool of the host and the validators still refuse Inference slots on self-hosted. The RUNBOOK says so in one line.
- **D-V6-14 Where LiveKit Inference is the default.** Default: on Cloud connections it stays the recommended and pre-selected stack (D-V6-3); the console's connection page shows the plan's credits line ("Build: $2.50 of Inference a month, then requests fail") from a registry constant with its `as_of` date, never a live billing call (there is no documented billing API). Override: none.

### Panels (P)

- **D-V6-15 The notebook is a block, not a panel.** Default: a `notebook` `BlockType` with `NotebookBlockConfig {sections: [{id, kind: text|checklist|details|ink, title, caller_can_edit: false}], paper: plain|ruled|grid|legal, handwriting: bool}` (strict, `extra="forbid"` like every block config) and `NotebookBlockState {sections: {<id>: TextSection {text, author_edits[]} | ChecklistSection {items: ChecklistItem[]} | DetailsSection {items: DetailsItem[]} | InkSection {canvas_block_id}}, updated_at}`; tools `notebook_write(section_id, text | items | fields, mode: replace|append)` and `notebook_check(section_id, item_id, done)`; `describe_panel` gains a `notebook` case that renders the sections as bounded, fenced text; an `ink` section hosts a child `canvas` block by id (D-V6-16), so the notebook can land before the canvas and shows "Drawing board coming soon" until it does. The **"Notebook" preset** is a `wide` composite layout with a notebook block (text "Notes", checklist "Still needed", details "Summary", ink "Sketch"), a gallery and a status block. "Handwritten" typed notes stay a paper theme (the CSS fonts the insurance panel uses today); real handwriting is ink. Rationale: the insurance panel is a React component over an insurance-only `UiState.custom` (`web/src/panels/insurance_notebook/state.ts:48-58`); a block is configurable by any agent, validated by the api and readable by the model. Override: none.
- **D-V6-16 Ink travels on a new browser→agent text stream.** Default: topic `lkap.ui.ink` (the first browser→agent **text** stream; `lkap.ui.upload` is bytes and RPC payloads cap at about 15 KiB), one JSON line per message `{block_id, stroke_id, op: add|erase|clear, points: [[x, y, pressure]…] normalised 0..1, color, width}`, accepted by the worker only from the caller participant, only for a `canvas` block (or a notebook ink section's canvas) whose config sets `caller_can_draw`, at most 2 KiB per message, 20 messages a second and 2,000 strokes per block (a `canvas_stroke_limit` activity line when exceeded). Strokes live in `CanvasBlockState {width, height, background: none | asset:<id> | live_camera, strokes[], shapes[], snapshot_asset_id}`; the agent draws with `draw_on_canvas(block_id?, shapes)` (boxes, arrows, circles, text, paths; upsert by id) and `clear_canvas`. **Reading handwriting**: `read_canvas(block_id?)` asks the page for a PNG (`UiRequest.method="snapshot"`), the page sends it on `lkap.ui.upload` with the canvas block id — accepted when the block allows drawing (a second acceptance rule beside `requested`) — the worker stores it as a session asset of kind `frame` with `meta.source="ink"` (no new asset kind, so no migration on the `v5_002` check constraint) and runs `describe_asset` on it with the agent's vision model. A canvas or ink section on an agent whose LLM has no vision (the Cloud default `gemma-4-31b-it` is text-only, `providers.py:786-790`) gets a validator warning naming a vision-capable model. This **subsumes B9 annotation**: `background: asset:<pinned frame>` is "circle the dent"; `live_camera` overlays the shapes on the live video block. Rationale: `panels-and-tools.md` §2 item 9 and §1. Override: a dedicated `ink` asset kind (one migration) if the console needs to filter snapshots.
- **D-V6-17 Drawing library.** Default: `perfect-freehand` (MIT, a few kilobytes) for stroke outlines over an SVG the console owns, imported lazily so `/s/[slug]`'s first-load budget is unchanged (R-V2-18, `web/tests/check-bundle.test.ts`); tldraw (its own licence with attribution terms) and Excalidraw (MIT, but a megabyte-class bundle) are rejected. **Verify licence text and gzipped size at implementation** (V6-14's acceptance records both); the fallback is plain polylines with no dependency. Override: none.
- **D-V6-18 The `layout` block is a flat container.** Default: `layout` with `LayoutBlockConfig {kind: tabs|columns, children: [{block_id, label?}], columns?: 2|3}` and no state; children remain top-level entries of `PanelLayout.blocks` (the state map stays flat, patches and `describe_panel` unchanged); the composite panel renders a claimed child inside its container and not in the flat flow; the api validator refuses a child claimed twice, a child that does not exist, and a `layout` claiming another `layout`. Rationale: nesting would change the envelope every tool and the AG-UI adapter rely on. Override: none.

### Tools (T)

- **D-V6-22 Context placeholders.** Default: `{{ ctx.session_id }}`, `{{ ctx.agent_id }}`, `{{ ctx.caller_phone }}` (E.164, empty on web), `{{ ctx.caller_identity }}`, `{{ ctx.language }}`, `{{ ctx.timezone }}` (the caller's zone of R-V5-10; closes ask #150), `{{ ctx.channel }}` (`web|phone|text`) and `{{ var.<name> }}` (flow variables and extraction variables, D-V6-24) are substituted **on the worker at call time** in an HTTP tool's URL path and query, body template and pinned MCP/provider arguments — never in headers (secrets only), never in the URL's scheme or authority (the api validator refuses a placeholder before the first `/` after the host; `_render_url` already percent-encodes values).
