# LKAP Implementation Plan — work packages by wave

> **2026-09-18 update.** `docs/DECISIONS-W2.md` (D-W2-1…9) and `docs/LIVE_TEST_PLAN.md` are binding and win over this file wherever they differ. Wave 0 and Wave 1 are complete. The W2-AGENT-INTEGRATION and Wave-3 packages below were rewritten to match; two small Wave-2 packages (W2-CONTRACTS-FIX, W2-TEST-CONNECT) were added. Doc precedence: DECISIONS-W2 > CONTRACTS > ARCHITECTURE > INSURANCE_PACK_MAPPING > this plan.

Rules for every package:
- Read `docs/CONTRACTS.md` first; shapes there are binding. If a contract is wrong, stop and report — do not fork it.
- You own only the files listed. Packages in the same wave never touch the same file. Shared files created in Wave 0 are read-only afterwards unless a later package lists them.
- Python: `uv sync`, `uv run ruff check . --fix && uv run ruff format .`, `uv run mypy src/ --strict`, `uv run pytest -x -v` must all pass in your package before you report done. No `print()`, structlog only, async-first, Pydantic v2, `X | None`.
- Offline tests must pass with **no vendor keys, no `.env`, no network** (`pytest -m "not live"`). Live tests use `-m live` and need only `LIVEKIT_*` env.
- Never read or write `.env*`. Ship `env.example` only.
- Never touch the existing `other-project-agent` agent; our name is `lkap-agent`.
- Report: files created, commands run with results, deviations from contracts (should be none), open questions.

Owner types: **Opus** = integration-heavy / ambiguous; **Sonnet** = well-specified from contracts.
