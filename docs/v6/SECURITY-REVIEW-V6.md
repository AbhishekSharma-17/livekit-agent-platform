## 1. Executive verdict

The v6 wave at `bbc3dd8` is **sound for supervised local use** and **conditionally approved for waves 6–7**: no Critical finding, no cross-workspace read or write (the datasets tenant rule holds on every route and in the worker's lookup), no unauthenticated write path, no secret in a log, event, brief or fixture, and every new site that hands third-party or caller text to the model is fenced (`FENCED_SITES` gained five modules with the parity test). The new attack surface is the model's own authority: three **Medium** findings let a prompt-injected model (or a hostile tool result) do more than the design intends — write requestable blocks through `update_block` (S6-1), put a blocked tool result on the panel and read it back around the `tool_output` guardrail (S6-2), and stall the worker with an admin-authored rule pattern the safety scanner does not catch (S6-4). Those three are the gate. Twenty-two Low/Info rows are hardening (caller-edit bounds, dataset ingest edge cases, audit rows, price bounds, the MCP guardrail gap the V6-21 card already reserves) and go to V6-21, a web package or the next plan as §6 says.

**Rulings made here** (mirrored in `PLAN-V6.md` §7): **R-V6-2** (this sign-off, §8) — including the four ask decisions it carries: #27 (a shared per-session bound for edits and taps, non-gate), #38 (bindings after the guard, gate), #58 (the caller may remove any note; accepted as designed), #86 (caller notes render without links; non-gate).

## 7. Verified-good properties and residual risks

- **Tenant isolation of datasets** on every admin route, the internal lookup and the worker tool (§3.1; `test_another_workspaces_dataset_is_404_on_every_route`, `test_a_lookup_never_returns_rows_of_another_workspaces_dataset`, `test_a_tool_cannot_read_another_workspaces_dataset`).
- **The ink wire is bounded before it is read**: caller check, token bucket and size cap precede the read (§3.4); no stroke carries text; no drop is logged with content.
- **A caller cannot fill the session's file cap with snapshots**: a snapshot is stored only while a `read_canvas` awaits it (§3.4).
- **Caller edits are fenced data**: `caller_edit` ≤ 700 chars, recorded without the value, applied only through the state validators.
- **Placeholders never reach a host, a header or a secret**, at save and in the worker; rendered values are percent- or JSON-escaped; `caller_phone` is never logged (row 13).
- **Bindings write only `details` and `table` blocks of the agent's own panel**, capped, only on success (row 14).
- **The rules grammar has no evaluation surface** beyond `re.search` (row 15; S6-4 is the one gap).
- **Extraction values follow the privacy tiers in events** and the model writes only declared names (row 16).
- **Every new third-party or caller text site is fenced** (`untrusted.py:61-70`; the parity test).
- **The migration** `v6_002_datasets` chains from `v5_008_memory` (one head), rehearsed `upgrade → downgrade → upgrade` on SQLite with `alembic check` (`docs/v6/_briefs/migration-rehearsal-v6.md`), and `api/tests/test_migration_v6_002.py` repeats it; the `tools.kind` check, the model's `CheckConstraint` and `ToolCreate.kind` agree (the #17/#18 lesson held).
- **The MCP dataset upload reads a local file only in stdio mode** (§3.2).
- **No new route without a `ROUTE_POLICY` rule** (the fallback is admin + `*`).
