### V2-10 → V2-11 wire contract (panel blocks)

All state still travels in the one `lkap.ui.state` envelope stream. It uses the same `seq` rules: seq 1 is the platform snapshot after `on_session_start`, every patch is `last + 1`, and a resnapshot follows every 50 patches or a `get_snapshot`.

- **`UiState.blocks`**: `{<BlockSpec.id>: <state object>}`. The seq-1 snapshot carries every block of the resolved layout, and so does every later snapshot. Keys are block ids; ids never contain `/`. `v` is `2`. Values are plain JSON:
  - `status` / `notes` / `checklist` / `activity` / `custom` → `{}`. The four envelope blocks render `state.status`, `state.progress`, `state.notes`, `state.checklist` and `state.activity`, exactly the props of `web/src/panels/generic/blocks.tsx`, and the existing tools (`set_status`, `push_note`, ...) keep writing those envelope fields.
  - `form` → `{schema: <JSON schema>, values: {}, status: "idle"|"requested"|"submitted", submitted_at: float|null}`. The key is `schema`, never `schema_`.
  - `document` → `{asset_id: str|null, url: str|null, page: int (1-based), highlights: [{page, bbox: [x0,y0,x1,y1], note}]}`. `bbox` is page-relative 0..1, origin top-left. `show_document` writes a note as `bbox [0,0,1,1]` (the whole page), and `url` is always `https://`.
  - `gallery` → `{asset_ids: [str], selected: str|null}`. Every `image/*` asset pushed through `push_asset` (for example `pin_frame`) is appended to every gallery block **in the same patch** as its `/assets` append.
  - `table` → `{columns: [{key, label, type: string|number|boolean|date}], rows: [{id, ...cells}], selected_row: str|null}`. Every row has a string `id`.
  - `transcript` → `{show_tools: bool}`. `video` → `{source: "agent_avatar"|"user_camera"|"user_screen"|"track:<sid>", muted: bool}`. `kb_citations` → `{items: [{chunk_id, filename, score, text}]}`.
  - Initial state: the model defaults, seeded by any `BlockSpec.config` key that names a state field (for example `config.columns` on a table, `config.source` on a video).
- **Patch paths the worker emits** (all ops are the existing `UiPatchOp`):
  - `set /blocks/<id>` (`set_block`, `show_document`, `request_form`'s "requested" state).
  - `set /blocks/<id>/<field>` (`update_block`, one op per field).
  - `append /blocks/<id>/rows` and, when new keys appear, `set /blocks/<id>/columns` first in the same patch (`table_append`).
  - `append /blocks/<gallery>/asset_ids` (with `/assets`).
  - `set /blocks/<id>/items` (citations; replaced, never appended).
  - Form submit is one patch with three ops: `set …/values`, `set …/status = "submitted"`, `set …/submitted_at`. Cancel is `set …/status = "idle"`.
  - Packs may also use `append`/`upsert`/`remove` (keyed by `id`/`key`) and numeric indexes under `/blocks`.
- **Form round trip**:
  1. The worker sets the block to `status: "requested"`, with `values` = prefill.
  2. The worker RPCs `lkap.ui.request {v:1, method: "form", payload: {block_id, schema, prefill}}` with a **15 s** caller-side timeout. The browser's handler sees `responseTimeout` ≈ 8 s, because the SDK subtracts its 7 s round-trip allowance: a 10 s timeout measured live arrived as 3 s. The browser should reveal the form and answer **at once** with `{ok: true, payload: {}}`.
  3. The user's values come back as `lkap.agent.action {v:1, action: "form_submit", payload: {block_id, values: {...}}}` → `{ok: true}`.
  4. Dismissal is `form_submit {block_id, cancelled: true}` (additive), or a `form` RPC result `{cancelled: true}`.
  5. For compatibility the worker also accepts a `form` RPC result `{values}`, but don't hold that RPC open waiting for the user.
  6. If the RPC fails, the wait continues, because the block state already shows the form. So a panel that renders a `requested` form from a snapshot after a reconnect can still submit.
  7. Worker-side timeout is 120 s. After it, the block stays `requested`. A late `form_submit` is still stored and recorded, and the model is prompted with it.
  8. `form_submit` errors (`ok: false`): unknown block id, a non-form block, or `values` not an object.
- **`request_form` field schema**: `{type: "object", properties: {<name>: {title: <label>, type, format?, enum?}}, required?: [...]}` with types `string|number|integer|boolean`, `date` → `{type: string, format: date}`, `email` → `{type: string, format: email}`, `select` → `{type: string, enum: [...]}`. Property order is field order.
- **Other UI requests**: `show_block {block_id}` (fire-and-forget; 10 s caller timeout, which the browser sees as about 3 s, measured live; sent after `show_document`). `navigate` is not emitted by any built-in yet.
- **`block_action {block_id, name, data}`** → the pack's `on_block_action(ctx, block_id, name, data)`. The result payload is returned. With no hook it returns `{ok: true, payload: {}}`. A missing `block_id` → `ok: false`. `rewind` / `inject_user_text` currently answer `ok: false, "unsupported action"` (V2-18).
- **Session events** (timeline):
  - `block_update {block_id, block_type, op: "set"|"patch"|"cite"|"form_requested"|"form_cancelled"}`, one per helper call, never with the state.
  - `form_submitted {block_id, values}`.
